Fleet QR identifiers

Interactive demo · encoder written from scratch

A recreation of the QR identifier system I standardised for trucks and trailers in a production transport platform. The QR on this page comes from no library: the whole encoder — byte mode, Reed–Solomon correction over GF(256), block interleaving, all eight masks and their penalty function — is written by hand in this file’s JavaScript.

Change the content, the correction level and the logo size. The verdict on the right is not a simulation: it counts how many codewords the logo actually damages and compares them against each block’s real correction budget.

How it works, and why it is built this way


    

      
The payload matters more than the code

      
The first version stored a URL: you scanned the unit and the phone opened a page in the system. It looked fine in the office. It did not in the yard, where the signal is poor or absent, and the driver was left staring at a blank screen waiting for a page to load.

      
I changed the payload to plain text. The unit’s data travels inside the code itself, so the scanner shows it the instant it reads it, without asking anything of the network. Try the Plain text / A URL switch and watch the green screen: it is the difference between reading the unit and reading an address you still have to go and fetch.

    


    

      
The logo eats your error correction

      
A QR survives damage because it carries Reed–Solomon redundancy. Level L tolerates around 7% of the data being damaged; H, around 30%. Putting a logo on top is not decoration: it is deliberate damage, and it comes out of the same budget that is supposed to cover grime, a crease or a poor print run.

      
That is why the verdict above does not guess. Every module the logo covers belongs to a specific codeword; the program reads the drawn canvas back, keeps only the modules that actually changed colour — a white module under a white part of the logo damages nothing — groups them by block and compares them against what that block can correct, which is half its correction codewords. Push the logo up with the level on L and you will see the exact point where it breaks.

    


    

      
Resolution: a blurry module is a lost module

      
The labels are printed, laminated, and then live stuck to a truck. Generated at a few pixels per module, the logo came out pixelated and the module edges landed halfway between black and white; the scanner had to guess, and sometimes guessed wrong. Raising the output resolution was not a cosmetic detail: it gave the code back the margin it had already paid for in redundancy.

    


    

      
The bug where the logo lied about what it was

      
A client uploaded their logo.png and the labels started coming out with no logo and no visible error at all. The file was named .png, but inside it was a JPEG: someone had renamed the extension by hand.

      
The code trusted the file extension to decide how to open it, so it called the PNG reader with JPEG data. It failed, and it failed silently, because the call was prefixed with PHP’s @ operator, which swallows the error. I switched it to getimagesize(), which inspects the file’s real bytes instead of believing its name, applied the same detection across every component that generated downloads, and removed the suppressions that had kept the problem invisible. Try the two buttons under The logo the client uploads.

    


    

      
About the encoder

      
It is written from scratch for this demo, not copied from the client’s system. It implements byte mode with UTF-8, versions 1 to 10, all four correction levels, Galois field GF(256) arithmetic for Reed–Solomon, block interleaving, all eight masks and the penalty function that picks the best one.

      
I verified it before publishing: the output decodes correctly with zxing-cpp, the reference implementation behind phone scanners, and on payloads that fill the capacity exactly the matrix comes out bit for bit identical to that of an established library. A QR that does not scan would be the exact opposite of what this page claims to know how to do.

    

  


  
Written from scratch in JavaScript, no libraries. In the real system these identifiers link a unit to its maintenance logbook, its inspections and its trip assignments, and they are printed on labels that go on the truck and on the trailer.
