Design decisions

  • The lockout is automatic, not a user action. Nobody decides whether a unit with failing brakes goes on the road: the policy applies itself the moment the fault is marked. Undoing it is not optional either — the unit is only released when the critical item is cleared.
  • An incomplete or unsigned inspection cannot be closed. A half-done inspection saved as complete is worse than no inspection at all, because it creates false confidence.
  • The rule lives apart from data access. In the real system I split this into a policy layer and a repository layer, in revision_critica_policy.php and revision_critica_repository.php, so the business rule can be read and tested without touching the database.
  • The signature is captured with Pointer Events on a canvas, so it works with a finger on the driver’s phone, which is where it is actually used.
Written from scratch in JavaScript, no libraries. In the real system the signature and photos are embedded in the inspection PDF, and the lockout is reflected in the unit availability for trip assignment.
